Diagram MVF Metamodel - Per PDF (no missing elements)

Comment

The MVF metamodel as per the natural language (PDF) beta specification at www.omg.org/spec/MVF/1.0/Beta1/PDF

The MVF metamodel presented on this diagram is the master diagram for the MVF metamodel. It is based on the XMI-based metamodel and adds information that is in the RDF and PDF versions but missing from the XMI. It is assumed that the different versions of the specification have the following precedence.

1      XMI (used as the basis for the PDF-based UML metamodel

The XMI broadly corresponds to the diagrams in the PDF, but some elements shown in the PDF do not appear in the XMI - some of the issues addressed here are documented at: issues.omg.org/issues/spec/MVF)

2      PDF (additional metamodel elements in the PDF version, such as MVFElement, are added to the XMI-based metamodel.

The PDF version is assumed to have highest precedence because this provides information about both the XMI and RDF versions.

3      RDF (all elements of the RDF-based metamodel retained "as imported" unless otherwise noted).

Because the purpose of this model is to provide a UML profile for MVF, it is logical to base it on the XMI (i.e. XMI) version of the metamodel.

  

The main reason for this precedence assumption is that it best preserves the XMI specification, which is the version intended to be used for modelling in UML. This model provides fixes for the problems encountered with XMI and PDF versions based on the RDF specification. In order to provide an RDF interface to UMlL models created with the MVF profile presented here, traceability links between UML classes/attributes to equivalent RDF elements/properties are provided.

 

The MVF PDF specification is not clear about the mapping between the associations shown on the metamodel and the equivalent object properties that implement relationships in OWL. However, it is clear from the RDF specification that all the relationships are derived directly from owl:topObjectProperty (the object property that relates every two individuals).

 

Because the MBOE metamodel extends MVF with SKOS relations that are not captured by the MVF metamodel, an additional assertion is shown to assert that the MVF Generalization relationship subsets the SKOS property is in semantic relation with. The equivalence of MVFEntry and skos:concept is also asserted per Section 4 of the PDF under the heading Model Element.

 

In the course of creating this metamodel (which combines information from all three versions, but is based on the XMI), it was found that the RDF version appeared to be more correct and complete. In future work it may be useful to align the UML profile with the RDF version directly and bypass the XMI. Given that this metamodel is based on the Beta specification, however, it would be better to submit the problems identified here as issues and wait for the full release (which will hopefully fix the several problems that are causing the current PDF/XMI/RDF misalignment).

 

Note that diagrams showing all the annotations in the RDF file are not included with this model (unlike for SKOS). This is because a full set of annotated diagrams for all the MVF ontologies is available in Section 9 of the MVF Specification PDF (note that these have not be checked for consistency with the RDF by this author).
